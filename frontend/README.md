# IPTV Control — Angular Material админка (v0.2.0)

Современный административный интерфейс IPTV-платформы. Самостоятельный frontend Angular, работающий через ранее созданный NestJS API без изменения SQL-миграций.

## Что готово

- Экран входа (локальный пользователь и OIDC по коду настроенного backend-провайдера), JWT access token в памяти, HttpOnly refresh-cookie (без localStorage для токенов), обновление сессии при перезагрузке страницы и ответе 401.
- Светлая и тёмная тема; крупные формы, современная типографика Manrope / DM Sans; Angular Material, адаптивное меню и таблицы.
- Переключение провайдеров с учётом RBAC; ограниченные пользователи запрашивают данные только с `providerId`.
- Главная страница с ограниченной сводкой, построенной на реальных записях каталога (без выдуманной статистики).
- Провайдеры: список, поиск, создание, редактирование, лимиты терминалов и одновременных просмотров.
- Каналы: поиск, фильтр типов приложений, постраничный просмотр, создание, редактирование, удаление.
- LIVE/DVR: главный/резервный URL, протокол, приоритет, режим архива, провайдер-специфичные URL.
- Плейлисты: список, создание, параметры, конструктор drag-and-drop, сохранение массива `stream_ids` в API.
- Жанры и типы приложений: список и редактирование через существующий API. Для существующего жанра текущий backend не возвращает список `provider_ids`, поэтому UI безопасно изменяет только название и возрастной признак, не трогая связи провайдеров.

**Не реализовано в этом этапе:** абоненты, терминалы, EPG-импорт, отправка сообщений, физическая проверка работоспособности источников, управление OIDC-провайдерами через UI и backend API метрик. Страницы не имитируют эти функции. Доступность некоторых кнопок зависит от прав пользователя.

## Требования

- Backend NestJS уже запущен по `http://127.0.0.1:4012`.
- Node.js, совместимый с Angular 22: `^22.22.3 || ^24.15.0 || ^26.0.0`.
- Angular 22.2 и Angular Material 22.2, TypeScript 6.0.
- Файлы шрифтов не включены: Manrope / DM Sans / Material Symbols загружаются браузером по HTTPS с Google Fonts, если внешний доступ разрешён; иначе используются системные резервные шрифты. При выпуске в закрытую сеть настройте собственную раздачу веб-шрифтов с соблюдением лицензий.

## DEV — запуск

```bash
cd /usr/local/nodejs/dev/iptv_front
unzip /path/to/iptv-admin-angular-v0.2.0.zip
mv iptv-admin-angular frontend
cd frontend
npm install
npm start
```

Открыть `http://127.0.0.1:4200` (при работе с удалённым сервером — SSH tunnel). Angular dev-server слушает только loopback, а его proxy.conf.json отправляет `/api/*` в NestJS на 4012.

Если разрабатываете на другом компьютере, `proxy.conf.json` должен указывать на доступный адрес вашего backend. **Не публикуйте HTTP API в интернет**; используйте HTTPS через Nginx.

При входе новый access JWT хранится только в памяти браузера. Обновление выполняется при перезагрузке страницы через HttpOnly-cookie `iptv_admin_refresh`.

### Важное про CORS и cookie

Для **одного домена** frontend и backend используйте конфигурацию Nginx из этого архива: `/` отдаёт Angular, `/api/` проксирует на localhost:4012. Тогда не требуется CORS, а refresh-cookie работает как same-origin. Это рекомендуемый вариант для DEV/PROD.

Если используете отдельный адрес Angular dev-server, в backend `.env` задайте `ADMIN_WEB_URL=http://localhost:4200` и `CORS_ORIGINS=http://localhost:4200` (Origin должен строго совпадать). Для OAuth/OIDC предпочтительно единый HTTPS-домен.

В примере `proxy.conf.json` браузер запрашивает `http://localhost:4200/api/v1/...`, а Node проксирует на `127.0.0.1:4012`. **Не открывайте `127.0.0.1:4200`, если в `ADMIN_WEB_URL` указан `localhost:4200`: для проверки Origin это разные адреса.**

## PROD — сборка

```bash
npm install  # первый запуск; создаст package-lock.json
npm run check
npm run build
mkdir -p /var/www/iptv-admin
cp -a dist/iptv-admin-ui/browser/. /var/www/iptv-admin/
```

Создайте HTTPS virtual host Nginx, добавьте фрагмент из `nginx-frontend.example.conf`. Обеспечьте, чтобы внутренний `127.0.0.1:4012` не был доступен публично.

Для NestJS в PROD: `NODE_ENV=production`, `COOKIE_SECURE=true`, `PUBLIC_API_URL=https://YOUR_HOST/api/v1`, `ADMIN_WEB_URL=https://YOUR_HOST`, `JWT_SECRET` не короче 32 символов. Проверьте работу login/refresh/logout через один домен.

### Примечания по безопасности

- Для входа по OIDC используйте только заранее настроенный `auth.oauth_providers.code`, зарегистрированный в NestJS. После первого входа новая учётная запись остаётся `pending` до назначения прав.
- В Angular нет локального сохранения JWT. Устройство может войти повторно через refresh-cookie.
- Операции редактирования должны проверяться на backend; скрытие кнопок на frontend не является защитой.
- Backend предоставляет только списки по 200 записей максимум и без total-count. Поэтому показатели главной страницы отражают **первые 200**, а не абсолютную статистику 60 000 абонентов. При развитии проекта нужны отдельные aggregate API.
- Каналы, доступные выбранному провайдеру, могут включать глобальные записи. Backend определяет, какие из них можно редактировать. Если права только провайдерские, не пытайтесь редактировать глобальные каналы (backend вернёт 403).
- Публикация ссылок HLS пока не защищена отдельными токенами по согласованному решению.

## Важно: статус проверки

Это кодовой пакет. В изолированной среде отсутствовал доступ к реестру npm. Если `npm install` нельзя выполнить, проверить сборку `ng build` здесь невозможно; выполните её на сервере и пришлите лог при ошибках.

### Повторяемая установка зависимостей

После первого успешного `npm install` сохраните сгенерированный `package-lock.json` в Git. В дальнейшем используйте `npm ci` для воспроизводимых установок.
