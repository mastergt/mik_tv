# IPTV Portal v0.8.1 — MAG250 + диагностика (Stage A.2)

Обновление **только** каталога `portal/`. Предназначено для установки поверх работающего v0.8.0 в `/usr/local/nodejs/dev/iptv_front/`. Не меняет `backend/`, `frontend/`, PostgreSQL `iptv_front`, `.env` и порт NestJS **4012**.

## Что появилось

- Лёгкий платформенный адаптер MAG250/MAG2xx для встроенного API Infomir `gSTB` / `stb` (и fallback на `stbPlayerManager`, если он доступен). В Chrome без такого SDK по умолчанию используется прежний HTML5/hls.js.
- Раздельные native playback solution: `ffmpeg` для HLS, `rtp` для UDP/RTP, `rtsp` для RTSP, `ffrt` для HTTP TS, `auto` для остальных адресов.
- Инициализация native player, chromakey (0x000008), fullscreen PIG и расположение видеослоя позади HTML-интерфейса. Подтверждение старта по событию `stbEvent.onEvent(4)`, ошибки/остановка по `5`/`1`, timeout 30 сек и fallback источников через уже существующий `App.playSources`.
- Пульт: стрелки, OK, Back, цифры сохранены. Для MAG дополнительно красная/F1 — каналы; зелёная/F2 — EPG; жёлтая/F3 — избранное; синяя (keyCode 406) — диагностика.
- Диагностика по **F9** на ПК или `?diag=1` в URL, также синяя кнопка MAG. Показывает User-Agent, SDK, выбранный движок, ключевые события проигрывания. Переключение движка Auto / HTML5 / MAG250 в диагностике перезагружает страницу с `?engine=...`.
- На MAG минимизированы градиенты/тени и отключено создание HTML5 video-сегментов. Исходные темы Modern/Classic и работа Chrome сохраняются.

### Установка

```bash
cd /usr/local/nodejs/dev/iptv_front
cp -a portal portal.backup-v0.8.0
unzip -o /path/to/iptv-portal-mag250-v0.8.1.zip
node portal/tests/check.cjs
node portal/tests/mag-adapter.test.cjs
```

Никаких npm-зависимостей, SQL-миграций или перезапусков backend нет. Для Nginx со статической отдачей достаточно обновить страницу (новые имена JS/CSS используют `v=0.8.1`). Если на устройстве очень агрессивный кеш, очистите кеш портала/перезапустите приставку.

### Проверка на ПК без приставки

Откройте существующий URL портала (например, `http://SERVER/portal/?diag=1`). Должно быть указано `Движок: html5`, `Native API: нет`, `SDK: none`.

Для офлайн-проверки интерфейса:

```bash
node portal/tests/mock-server.cjs
# http://127.0.0.1:4411/portal/?diag=1
```

### Проверка MAG250 на физической приставке

1. Откройте портал, добавив к URL `?diag=1`, или нажмите синюю клавишу пульта.
2. Убедитесь, что выбран `mag250`, а `Native API: есть`; запишите User-Agent, наличие `gSTB`/`stb` и версию прошивки отдельно.
3. Проверьте каналы с **HLS** и **UDP**, последовательное переключение, переключение резервного источника при сбое основного, клавиши и полноэкранный видеослой.
4. Если экран чёрный, в диагностике посмотрите событие `4` (начало), `5` (ошибка), `1` (конец), а также `timeout 30 с`. Не включайте экспериментальные режимы прошивки без отдельной проверки.
5. Проверьте, что вход абонента работает, только если клиентский API опубликован по **HTTPS** либо внутри доверенной изолированной сети. По общедоступному HTTP нельзя безопасно передавать пароль и bearer-токен.

**Ограничения:** MAG250 пока нет для физических тестов. Этот релиз подготовлен по документации и по старому `mag200/system.js`; аппаратная работа на конкретной прошивке, TLS и видеодекодирование не подтверждены. На MAG250 может потребоваться корректировка chromakey/параметров видео при реальных тестах. Для других приставок (Eltex, Dune, TVIP, Amino) отдельные адаптеры пока не реализованы.

### Диагностические URL

- `/portal/?diag=1` — открыть диагностический экран
- `/portal/?engine=mag250&diag=1` — принудительно выбрать MAG250
- `/portal/?engine=html5&diag=1` — принудительно выбрать HTML5/hls.js
- `/portal/?engine=auto` — автоматический выбор

При ручном выборе MAG250 в Chrome будет показано отсутствие Native SDK — это ожидаемо, не используйте такой режим для обычных пользователей.
